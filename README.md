# simsab-resources

Further reading and deep-dive resources that accompany the live courses on
[courses.simsab.net](https://courses.simsab.net). Served at
**https://resources.simsab.net** from Cloudflare Pages, like the course site.

The site is static HTML. There is no framework and no database. Two small
Node scripts do the housekeeping: one builds the search index and the index
pages, and one prints each resource to PDF.

## Structure

```
public/
  index.html                     Library index: search, filters, all resources, concepts A–Z
  <collection>/index.html        Collection page (a course, or a topic collection)
  <collection>/<slug>.html       One resource  →  /<collection>/<slug>
  <collection>/img/              Figures used by that collection
  <collection>/pdf/<slug>.pdf    Generated PDF for each resource (committed and deployed)
  <collection>/templates/<slug>.html      Printable worksheet (one A4 page)
  <collection>/templates/pdf/<slug>.pdf   Generated PDF of that worksheet
  css/resources.css              Styles specific to this site
  css/templates.css              Worksheet layout, on screen and in print
  js/library.js                  Search and filters on the index page
  js/resource.js                 "On this page" behaviour on resource pages
  data/search-index.json         Generated by the build
  _headers, robots.txt           Cloudflare headers; asks search engines not to index
scripts/
  build.mjs                      Search index, index pages, link check
  pdf.mjs                        PDF generation
templates/resource.html          Starting point for a new resource page
```

Current collections:

- `coordination-collaboration-ai`: the ten resources for *Leading Coordination
  and Collaboration in AI-Accelerated Organisations*, grouped by module.
- `effective-meetings`: three resources for *Designing and Facilitating
  Meetings That Move Work Forward*, grouped by module.
- `product-ownership`: ten resources and twelve printable templates for
  *Product Ownership: Deciding What to Build and Why*, grouped by module.

## Shared styling with the course site

Every page loads the course site's stylesheet first, then this site's own:

```html
<link rel="stylesheet" href="https://courses.simsab.net/css/styles.css">
<link rel="stylesheet" href="/css/resources.css">
```

So fonts, colours, typography, hero, cards, buttons and footer come from one
place: `simsab-courses/public/css/styles.css`. A change there shows up here on
the next page load. `resources.css` only adds components the course site does
not have (search, filters, table of contents, reading layout, print rules) and
only uses the course site's CSS variables.

The fonts are loaded from courses.simsab.net too. This works because the course
site already sends `Access-Control-Allow-Origin: *`. If that header is ever
removed from the course site, the fonts here fall back to the system fonts.

## Everyday tasks

```
npm install                    once
npx playwright install chromium   once, for PDF generation
npx wrangler login             once

npm run build                  rebuild search index and index pages, check links
npm run pdf                    create PDFs for new or changed resources
npm run dev                    local preview at http://localhost:8788
npm run deploy                 build + pdf + deploy to Cloudflare Pages
```

### Edit a resource

Edit the HTML file in `public/<collection>/`, then run `npm run deploy`. The
build updates the search index, and the PDF step regenerates only the PDFs of
pages that changed.

### Add a resource

1. Copy `templates/resource.html` to `public/<collection>/<slug>.html` and
   follow the notes at the top of the template.
2. Update the previous/next links on the neighbouring resources.
3. Run `npm run build`. The resource appears on the library index, the
   collection page and in search. The build stops with a list of problems if a
   link or `#anchor` points nowhere.
4. Run `npm run pdf`.

### Add a collection

Create `public/<new-collection>/` with an `index.html` (copy
`public/effective-meetings/index.html` and change the text). Keep the
`<!-- build:... -->` markers; the build fills them. The collection filter on
the index page appears automatically once there is more than one collection.

### Cross-references

Links between resources are ordinary root-relative links, optionally to an
anchor, for example
`/coordination-collaboration-ai/facilitating-convergence#closure-reaching-a-decision`.
Every `h2` and every defined term (`<p class="term" id="...">`) has an id.
Anything marked with `data-concept="..."` is listed in the Concepts A–Z index.
The build checks all of these links.

### Printable templates

A template is an HTML page in `public/<collection>/templates/` with
`<meta name="template:collection" ...>` in its head. It shows a preview of the
worksheet on screen and prints as exactly one A4 page, using the building
blocks in `css/templates.css` (`.field`, `.field.row`, `.grid-2x2`,
`.sheet-table`). Copy an existing template to start a new one. Templates are
linked from the "Templates" section of the matching resource page and from
the collection page; add the link in both places by hand. `npm run pdf`
creates their PDFs along with the resource PDFs.

## PDFs

`npm run pdf` opens each resource page in headless Chromium and prints it with
the print rules at the end of `resources.css` (A4, branded header, page
numbers, links pointing to resources.simsab.net). Output goes to
`public/<collection>/pdf/<slug>.pdf`, and `pdf-manifest.json` records a hash of
each page and the stylesheets, so unchanged PDFs are skipped.

- Regenerate everything, for example after a design change on the course site:
  `npm run pdf -- --force`
- One resource only: `npm run pdf -- --only facilitation-toolkit`

If the course site folder sits next to this one (`../simsab-courses/public`),
the script reads the shared stylesheet and fonts from disk, so the PDFs match
your local design and no network access is needed. Otherwise it loads them from
courses.simsab.net. Use `--shared-dir <path>` to point somewhere else.

## Deployment (first time)

1. `npx wrangler pages project create simsab-resources` (production branch: `main`)
2. `npm run deploy`
3. Connect the domain. The DNS for simsab.net is managed at GoDaddy, so this
   takes two steps, in this order:
   1. In the Cloudflare dashboard, open the Pages project → Custom domains →
      Set up a custom domain → `resources.simsab.net`. Cloudflare then shows
      the CNAME record it expects. Do this first: a CNAME that points to
      Pages before the domain is added in Pages returns an error page.
   2. In GoDaddy, open DNS for simsab.net and add a record:
      Type `CNAME`, Name `resources`, Value `simsab-resources.pages.dev`,
      TTL default (1 hour).
   Cloudflare checks the record and issues the certificate, usually within
   a few minutes and at most a day. The status in Custom domains changes to
   Active when it is done. The course site at courses.simsab.net is connected
   the same way, so its CNAME record in GoDaddy is a useful reference.

## Access

The site is public but not indexed by search engines (`_headers`,
`robots.txt` and a robots meta tag on every page). If the resources should be
limited to participants, Cloudflare Access (Zero Trust → Access →
Applications) can protect `resources.simsab.net` with a one-time PIN sent to
an allowed list of email addresses, without any code changes here.
